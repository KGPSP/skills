## Pre-change rules

Before any code change in this project, verify which test layer is affected and follow the
hierarchy below.

### Test hierarchy (this project)

| Layer | Required | Tool | Anti-pattern |
|---|---|---|---|
| Unit | every PR | {{UNIT_TOOL}} | testing private state, asserting CSS classes |
| Integration HTTP | every PR | {{INTEGRATION_HTTP_TOOL}} | manual port management |
| Integration DB | every PR (when SQL touched) | Testcontainers Postgres | mocking `pg`/`psycopg`/`pgx` |
| E2E smoke | every PR | Playwright | sztywne `waitForTimeout` |
| E2E full | pre-release | Playwright (multi-browser) | — |

### Version-sensitive frameworks

For Next.js: before any change to App Router, Route Handlers, or Server Components, read the
**bundled version docs** at `node_modules/next/dist/docs/` — do NOT rely on model memory.

For Vitest/Jest: check the installed version with `{{PACKAGE_MANAGER}} list vitest` (or jest)
before assuming API shape (e.g., `vi.mocked` vs `jest.MockedFunction`).

For Testcontainers: `@testcontainers/postgresql` API differs significantly between v9 and v10.
Verify version before writing fixtures.

## Selector priority (UI tests)

```
1. getByRole({ name })           ← preferred default
2. getByLabelText                 ← form inputs
3. getByPlaceholderText           ← when no label
4. getByText                      ← for static text
5. getByTestId                    ← escape hatch only
```

Using `getByTestId` requires a code comment explaining why semantic queries failed.

## Mocking boundaries (hierarchical)

```
MSW                    → HTTP boundary (external APIs, auth, payment, third-party)
vi.fn() / jest.fn() / unittest.mock / interface-substitution → local modules
Testcontainers         → SQL boundary (no mocking)
```

Mixing layers (e.g., MSW for DB) is an anti-pattern.

## Async Server Components (Next.js only)

Async RSC are NOT supported in Jest/Vitest officially. Pokrycie → Playwright e2e.
Synchronous Server Components OK in Jest/Vitest + jsdom.

## Definition of Done (per task)

- [ ] Failing test PRZED implementacją (TDD).
- [ ] Test pokrywa happy + edge case (Beyoncé Rule).
- [ ] DAMP — test czyta się jak spec, bez magicznych helperów.
- [ ] Build clean (warnings as errors).
- [ ] Coverage threshold met (see `configs/{{CONFIG_FILE}}`).
- [ ] PR diff ≤ 300 lines (justified if more, hard split at 1000).
- [ ] CI green: lint + typecheck + unit + integration + smoke e2e + dependency review.

## When to escalate (don't guess)

- Conflicting requirements between issue and existing code → STOP, ask human.
- API change that may break public consumers (Hyrum's Law) → STOP, write `api-impact.md`.
- Removing code that seems unused but has no documented reason (Chesterton's Fence) → STOP, find original commit, document why before removing.
- Build failures that you cannot reproduce locally → STOP, ask, do not "fix" by disabling tests.
